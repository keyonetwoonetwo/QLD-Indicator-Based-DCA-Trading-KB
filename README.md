# KB증권 OPEN API를 활용한 QLD 조건에 따른 적립식 프로젝트

## 주의사항

### 1. OPEN API 키와 시크릿, MAC주소, 텔레그램 봇 키 및 채팅 ID는 중요한 인증정보입니다. 
외부에 노출되지 않도록 철저히 관리하세요.
   
### 2. 본 프로젝트는 투자권유나 자문이 아니며, 수익을 보장하지 않습니다.

### 3. 본 프로그램이 정상적으로 작동하더라도 시장 상황 및 매매 전략에 따라 손실이 발생할 수 있으며, 원금 손실의 가능성이 있습니다.

### 4. 주문 전송 또는 접수는 체결 완료를 의미하지 않습니다. 
미체결, 부분체결, 주문 거절, 취소 등이 발생할 수 있으며, 실제 체결 여부는 계좌 보유내역과 주문 내역을 통해 확인해야 합니다.

### 5. 데이터 오류, 네트워크 장애, API 장애, 프로그램 오류 및 기타 예기치 못한 문제로 인해 예상하지 못한 손실이 발생할 수 있습니다.

### 6. 본 프로젝트는 AI기반 바이브 코딩방식으로 개발되었습니다. 
테스트를 실시하였으나, 발견되지않은 오류나 예외사항이 존재할수 있으므로, 실제 계좌에서의 사용 전 사용자의 충분한 검토와 테스트가 필요합니다.
   
### 7. 모든 투자 결정과 책임은 사용자 본인에게 있습니다.
   
### 8. 작성자는 본 프로그램의 사용으로 발생하는 어떠한 투자 결과 및 손실에 대해서도 법적 책임을 지지 않습니다.
   

## 프로젝트 설명

### 1. 프로젝트 개요

KB증권의 OPEN API를 기반으로, 매일 일정금액 소수점 적립이 아닌, 조건에 따른 소수점 적립을 다르게 할수있도록 스크립트를 구현했습니다.

### 2. 프로젝트 구조 설명

프로그램은 매수 대상 ETF의 분봉 종가를 활용한 임시 일봉과, 기준 ETF의 과거 확정 일봉에 당일 분봉 종가를 반영해 계산한 임시 200일 이동평균선(MA200), CNN 공포탐욕지수를 조합하여 시장 상황을 판단합니다.

이러한 조건에 따라 사전에 설정된 12가지 매수금액 중 하나를 선택하고, 해당 금액만큼 소수점 주식을 매수합니다.
   
#### ETF 역할

- SIGNAL : 200일선과 비율로 설정된, 기준선을 제시
- MAIN : 소수점으로 적립하는 메인 자산
- SAFE : 현금파킹을 위하여 사용되는 자산
  
#### 거래방식 구현

- 매수 주문은 사전에 설정한 금액만큼 지정가주문으로 실행함니다.
- 전략에서 판단한 조건을 기준으로 **매수 지정가 +0.1%, 매도 지정가 -0.1%** 적용함니다.
- 안전자산은 온주 기반의 지정가주문으로 실행합니다.
- 지정가 주문에 따라서, 체결이 되지 않을수도 있습니다.

#### 대기자금 파킹 및 현금성 자산 보유

- 프로그램은 대기자금의 비율을 조정할 수 있습니다.
- 매주 첫 거래일에 보유 현금을 확인하여, 설치 시 설정한 SAFE 목표현금 배수 × '기준선 이하·음봉·공탐 낮음' 조건의 매수금액을 최소 현금 유지 기준으로 사용합니다.
- 첫 거래일의 보유 현금이 최소 현금 기준 이상이면 SAFE를 매도하지 않습니다.
- 보유 현금이 최소 현금 기준보다 부족하면, 부족한 현금을 확보하기 위해 SAFE를 매도합니다.

```text
SAFE 목표현금 배수 : 5(기본값)
기준선 이하·음봉·공탐 낮음 매수금액 : $40(기본값)
시작일 최소 현금보유액 : $200(기본값)
```
※ 실제 SAFE 매도는 정수 주식 단위의 지정가 주문으로 처리되므로, 매도 가능 수량과 체결 여부에 따라 확보되는 현금은 부족 금액과 다를 수 있습니다.

#### 텔레그램을 통한 정보 통지 및 백업

- 설치 시 텔레그램 봇 토큰과 Chat ID를 입력하면 당일 상황 판단, 거래 발생 시 거래내역, 백업파일이 전송됩니다.
- 백업파일을 이용하면 새로운 서버로 이동하거나 재설치한 뒤 복구하여 기존 전략을 이어갈 수 있습니다.

## 설치전 사전작업(공통)

### 프로젝트 사용전 사전준비

#### KB증권

- OPEN API를 미리 신청, Client Id, Client Secret을 발급
- 초기 설치에서 관리 대상 ETF는 존재하지 않아야함
- KB증권에서 레버리지 ETF를 거래할 수 있도록 준비합니다. (레버리지 적립이 아니면 상관없음) 
  - 타 증권사의 ETP 거래확인서를 첨부하여 허가를 받거나, 증거금 등을 통해 미리 거래 가능 상태로 준비합니다.

#### 텔레그램

- 텔레그램 봇 토큰을 발급합니다.
- 텔레그램 Chat ID를 확인합니다.
- 다음 주소를 이용하여 대화방 ID를 확인할 수 있습니다.

```text
https://api.telegram.org/<봇토큰>/getUpdates
```

#### 인터넷 회선의 공인 IPv4 및 설치 기기의 MAC번호 확인

서버에서는 사용 중인 서버의 IPv4를 확인하고, Android / Termux에서는 다음 명령으로 확인할 수 있습니다.

```bash
curl -4 ifconfig.me
```

MAC : 기기의 MAC주소 확인하기, 안드로이드 : 폰의 상태정보에 wifi MAC주소 확인

KB증권으로 정보를 전송할때, IPv4와 MAC주소를 함께 전송합니다. 접속 IP가 변경되는 환경에서는 인증 또는 API 요청이 실패할 수 있으므로, 안정적인 인터넷 연결 환경을 권장합니다.

## 설치방법 안내(Android / Termux 기준)

- Linux 서버와 Android / Termux의 설치 절차는 대부분 동일합니다.
- 주요 차이점은 자동실행 스케줄러 구성 방식입니다.
  - Linux 서버: `systemd timer`
  - Android / Termux: `crond`
- 본 매뉴얼에서는 설명의 편의를 위해 공유기 Wi-Fi에 연결된 Android 공기계를 기준으로 설치 과정을 설명합니다.
- Linux 서버에 설치하는 경우에도 동일한 설치 파일과 `setup.sh`를 사용하며, 서버 접속 및 파일 업로드 방법만 환경에 맞게 진행하면 됩니다.
- Android의 경우 Termux:Boot 설치, Wake Lock 활성화, 배터리 제한 없음 설정을 수동으로 진행해야 합니다.

### 1) Termux 기본 업데이트

```bash
pkg update -y && pkg upgrade -y
```

업데이트 중 아래와 같은 질문이 나타날 수 있습니다. 변경할 이유가 없다면 기본값으로 엔터를 눌러 진행합니다.

```text
*** openssl.cnf (Y/I/N/O/D/Z) [default=N] ?
*** sources.list (Y/I/N/O/D/Z) [default=N] ?
*** bash.bashrc (Y/I/N/O/D/Z) [default=N] ?
*** profile (Y/I/N/O/D/Z) [default=N] ?
```

### 2) 저장소 접근 권한 설정

```bash
termux-setup-storage
```

### 3) 설치 폴더 생성

```bash
mkdir -p ~/kb-qld
cd ~/kb-qld
```

### 4) 다운로드한 ZIP 복사

아래 명령어와 동일한 압축파일을 Android 다운로드 폴더에 받았다고 가정합니다.

```bash
cp ~/storage/downloads/KB-QLD-release.1.9.zip .
```

### 5) unzip 설치 및 압축 해제

```bash
pkg install -y unzip
unzip KB-QLD-release.1.9.zip
```

### 6) 설치 폴더 진입

```bash
cd KB-QLD-release
```

### 7) 실행 권한 부여

```bash
chmod +x *.sh
```

### 8) 설치 시작

```bash
./setup.sh
```

### 9) 설치과정 입력 내용

실행 환경을 선택합니다.

```text
[1] Linux
[2] Android / Termux

선택 [1/2]:
```

`[2]`를 선택하면 아래와 같은 메시지를 확인합니다.

```text
Android / Termux 설치를 선택했습니다.

설치를 계속하기 전에 다음을 확인하세요.

- Android 배터리 최적화에서 Termux 제외
- Termux 알림 패널에서 Wake Lock 활성화

위 설정을 완료했습니까? [y/N]:
```

일봉의 종가로 사용하기위한 시간을 설정합니다.

```text
신호 시각 SIGNAL_TIME [HH:MM:SS]:
```

신호 및 거래 ETF 티커를 입력합니다.

```text
SIGNAL_SYMBOL [기본값]: 
MAIN_SYMBOL [기본값]: 
SAFE_SYMBOL [기본값]: 
```

신호 ETF의 기준 비율을 설정합니다.

```text
RISK_THRESHOLD [기본값]:
```

CNN 공포탐욕지수의 구간값을 설정합니다.

```text
낮음 구간 상한 [기본값]: 
중간 구간 상항 [기본값]:
```

SAFE로 파킹이 아닌 매수가능한 현금보유액을 설정합니다.

```text
SAFE 목표현금 배수 [기본값]: 
```

KB API Key, 시크릿, open api주소(엔터), 계좌번호, IP주소(사용할IP), MAC주소를 입력합니다.

```text
KB_CLIENT_ID:
KB_CLIENT_SECRET:
KB_API_BASE_URL [https://developer.kbsec.com:32484]:
KB_ACCOUNT_NO:
KB_IPv4:
KB_MAC
```

시세조회를 위한 등록한 ETF의 거래소 코드를 입력합니다.

```text
(NAS: 나스닥, NYS: 뉴욕거래소, AMX: 아멕스)
SIGNAL_SYMBOL: 
MAIN_SYMBOL: 
SAFE_SYMBOL:
```

조건별 매수금액을 설정합니다.

```text
기준선 이상-양봉-공탐낮음 [기본값]:
기준선 이상-양봉-공탐중간 [기본값]:
기준선 이상-양봉-공탐높음 [기본값]:
기준선 이상-음봉-공탐낮음 [기본값]:
기준선 이상-음봉-공탐중간 [기본값]:
기준선 이상-음봉-공탐높음 [기본값]:
기준선 이하-양봉-공탐낮음 [기본값]:
기준선 이하-양봉-공탐중간 [기본값]:
기준선 이하-양봉-공탐높음 [기본값]:
기준선 이하-음봉-공탐낮음 [기본값]:
기준선 이하-음봉-공탐중간 [기본값]:
기준선 이하-음봉-공탐높음 [기본값]:
```

텔레그램 사용 여부 및 정보를 입력합니다.

```text
Telegram 알림을 사용하시겠습니까? [Y/n]:

Telegram Bot Token:
데이터 및 거래 알림 Chat ID:
백업 데이터 Chat ID [Enter = 알림 대화방과 동일]:
```

자료 백업시간은 기본적으로 뉴욕시간 기준 16:15로 설정되어 있습니다. 수정이 필요 없으면 기본값으로 진행합니다.

```text
Daily backup time in America/New_York [기본 백업시간]:

이 Telegram 백업 timer를 생성하고 활성화하시겠습니까? [y/N]:
```

거래 시간은, 분봉의 경우 설정시간의 +1분뒤부터 폴링을 시작합니다.

```text
거래 자동실행을 활성화하시겠습니까? (스케줄 표시) [y/N]:
```

자동실행을 위해 Termux:Boot 앱이 필요합니다.

```text
Termux:Boot가 설치되어 있습니까? [y/N]:
```

### 10) 설치 완료 이후 DRY_RUN 점검

```bash
./validate.sh
```

실행 후 DRY_RUN 검증 메시지를 확인합니다.

### 11) LIVE 전환

```bash
./enable-live.sh
```

안내에 따라 입력 및 코멘트를 작성한 뒤 LIVE 전환 메시지를 확인합니다.

### 12) 백업파일을 통한 복원 안내

기존 사이클 내용을 이어가며 복구하려면 `./setup.sh`를 통한 설치 이후 `DRY_RUN` 상태에서 `./recover_backup.sh`를 사용합니다.

설치 또는 복구 준비 과정에서 일부 오류 메시지가 나타날 수 있으므로, 복구가 목적이라면 `.env`가 생성된 상태인지 확인한 뒤 `DRY_RUN` 상태에서 복구를 진행합니다.

Android 다운로드 폴더에 백업파일이 있는 경우:

```bash
./recover_backup.sh ~/storage/downloads/kb-qld-trader-backup-XXXXXXXX-XXXXXX-UTC.tar.gz
```

복구 방식은 두 가지입니다.

1. 현재 거래방식 유지
2. 백업 거래방식 복원

단 `.env`의 설정값은 자동 복구되지 않습니다.

복구 후 다음 명령으로 `.env`를 확인하고 필요한 경우 직접 수정합니다.

```bash
nano .env
```
